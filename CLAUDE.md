# CLAUDE.md — command-palette

Org-wide conventions (repo list, Hive-org boundary, package scopes, git workflow, commit
format, CI secrets) live in
[System-B90/.github CLAUDE.md](https://github.com/System-B90/.github/blob/main/CLAUDE.md).
This file covers what's specific to command-palette.

## What command-palette is

The shared VSCode-style command palette, published as
`@system-b90/command-palette` to npm. Consumed by host apps.

## The one rule

Nothing here may know about a host app. No domain concepts, no routes, no copy
in the component tree — every string the palette renders arrives through
`labels`, and every command arrives through `useCommands` from the app that can
actually perform it.

Imports are limited to `react` and `@mui/*`, all peer dependencies. Adding a
runtime dependency is a deliberate decision, not a convenience.

## Languages

`src/labels/en.ts` and `src/labels/he.ts` ship the two tables, each behind its
own package subpath (`/en`, `/he`). **No other module in the package may import
either one** — that, plus `sideEffects: false`, is the only reason a host that
picks Hebrew does not also ship the English strings. `tests/labels.test.ts`
asserts it against `dist/`; do not "simplify" it by re-exporting the tables from
`src/index.ts` or adding a `language` prop that selects between them.

## Imports

Internal imports use the `@/*` alias enforced by
`no-restricted-imports`. `npm run build` runs `tsc-alias` after `tsc` to rewrite
those specifiers to relative paths in `dist/` — without it the published package
would not resolve. Keep the `.js` extension on every internal specifier; the
package is ESM.

## Tests

`tests/` covers `core/` only (registry, matcher, ranking, prefix parsing) and
imports from `dist/`, not `src/`, so it exercises what actually ships — hence
`pretest` builds. The React layer has no test harness here; UI behaviour is
covered by the consuming apps' E2E suites.

## Docs

Prose lives in `docs/` (mkdocs-material, nav in `mkdocs.yml`). `docs/api/` is
generated by TypeDoc from TSDoc comments in `src/` and is gitignored — never
hand-edit it. `npm run docs:serve` previews locally (needs
`pip install mkdocs-material mkdocs-typedoc`); `docs.yml` deploys to GitHub
Pages on tags.

Convention: *why* goes in source comments, *how* goes in `docs/`. The trade-offs
in `docs/architecture.md` are the ones most likely to be re-litigated — read them
before "simplifying" the registry, the matcher or the locale split.

## Git

Commit format: `Vibe-<PastTenseVerb> <description>` (e.g. `Vibe-Fixed`, `Vibe-Added`). No
`feat:`/`fix:`/`chore:` prefixes. Never commit directly to `main`/`master` — feature
branch + PR. Bump the package version deliberately before publishing — consumers pin
exact versions.
